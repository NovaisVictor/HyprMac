// =========================================================== Synopsis
== Synopsis
[verse]
// tag::synopsis[]
hyprmac layout [-h|--help] [--window-id <window-id>|--workspace <workspace>]
                 [--root] [--fail-if-noop]
                 (<target-layout>)...
hyprmac layout [-h|--help] --for-next-detected-window (tiling|floating)

// end::synopsis[]

// =========================================================== Description
== Description

// tag::body[]
{manpurpose}

// =========================================================== Options
include::./util/conditional-options-header.adoc[]

-h, --help:: Print help

--window-id <window-id>::
include::./util/window-id-flag-desc.adoc[]

--workspace <workspace>::
include::./util/workspace-flag-desc.adoc[]

--root::
Instead of the focused window, change the layout of the workspace tiling root node.
When you use this flag, `tiling` and `floating` become invalid values for `<target-layout>`.

--fail-if-noop::
Exit with non-zero exit code if already in the requested layout.
When you use this flag, the command permits only one `<target-layout>` argument.

--for-next-detected-window::
Don't change the layout of any currently existing window.
Instead, schedule the layout change, and apply it to the next window that HyprMac detects.
+
The scheduled layout change is applied both before and after the xref:guide.adoc#on-window-detected-callback[on-window-detected callbacks] are run,
so that the callbacks observe the scheduled layout, and so that the scheduled layout wins over the callbacks.
Running the `layout --for-next-detected-window` command again replaces the previously scheduled layout change.
+
When you use this flag, the command permits exactly one `<target-layout>` argument,
and `tiling` and `floating` are its only valid values.
The flag is incompatible with all the other flags.

// =========================================================== Arguments
include::./util/conditional-arguments-header.adoc[]

<target-layout>::
Possible values:
+
* `h_tiles|v_tiles|h_accordion|v_accordion|h_master|v_master|h_center_master|v_center_master` - Change both tiling layout and orientation in one go
* `tiles|accordion|master|center_master` - Change tiling layout but preserve orientation
+
`center_master` is the xref:guide.adoc#master-layout[master-stack] layout with the master in the middle, whatever the `master-placement` of the monitor is.
`master` clears this per-container override: the container follows `master-placement` again.
* `horizontal|vertical` - Change orientation but preserve layout
* `tiling|floating` - Toggle between floating/tiling mode
+
If several `<target-layout>` are supplied, then the first one that doesn't describe the currently active layout is applied.

// =========================================================== Examples
include::./util/conditional-examples-header.adoc[]

* Toggle between `floating` and `tiling` layouts (order of args doesn't matter): +
`hyprmac layout floating tiling`

* Toggle orientation (order of args doesn't matter): +
`hyprmac layout horizontal vertical`

* Toggle between `tiles` and `accordion` layouts (order of args doesn't matter): +
`hyprmac layout tiles accordion`

* Switch to `tiles` layout. Toggle the layout orientation if already in `tiles` layout: +
`hyprmac layout tiles horizontal vertical`

* Toggle between `tiles` and the xref:guide.adoc#master-layout[master-stack] layouts: +
`hyprmac layout tiles master`

* Toggle the master between the middle and the start (on a monitor with the default `master-placement = 'start'`): +
`hyprmac layout center_master master`

* Make the next window that opens floating: +
`hyprmac layout floating --for-next-detected-window`
